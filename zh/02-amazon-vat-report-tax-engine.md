# 亚马逊 VAT 计算报告怎么自动算税：给 VAT 服务商的系统设计拆解

> 原文发布在绯星科技博客：https://www.feixingtech.cn/blog/amazon-vat-report-tax-engine/

做跨境 VAT 服务的机构，最耗人力的环节往往不是注册，而是每个申报周期的算税。卖家把亚马逊 VAT 计算报告（Amazon VAT Transactions Report）发过来，会计在 Excel 里按国家、按税率、按抵扣项手工归类，再填到各国的申报表里。国家一多、卖家一多，错误率和周期就都上来了。

我们为一家跨境税务合规服务商搭建过一套覆盖 VAT 注册 / 转代理、算税、申报缴税、EPR 和授权代表的线上平台。这篇文章只拆算税这一块：亚马逊报告进来之后，系统是怎么把它变成可申报数字的。思路对想把自己服务做成产品的 VAT 服务商和税务代理应该有参考价值。

## 先说输入：亚马逊报告的结构

亚马逊 VAT 计算报告是一张按交易逐行记录的表，每一行包含：交易类型、代扣方（是亚马逊代扣还是卖家自行申报）、买家是否提供有效税号、发货国、到达国、税率、含税和不含税金额、币种等字段。

算税的本质就是：对每一行判断「这笔销售在哪个国家、按什么性质、以什么税率申报」，然后按国家和申报周期汇总。

## 核心设计：先分类，再算税

我们没有按国家逐个写规则，而是先把每一行交易归入 7 类销售。分类维度是三个字段的组合：

- 代扣方：亚马逊代扣（平台作为视同供应商）还是卖家自报
- 买家税号：买家是否为有有效 VAT 税号的企业
- 发货国 / 到达国：本国销售、欧盟内跨境、出口到欧盟外

三个维度组合后，交易会落到不同性质的类别里，例如本国销售、欧盟内跨境销售、面向有税号企业的供应、出口、平台代扣等。每一类的申报处理方式是固定的：有的按当地税率计销项税，有的按零税率申报并单独列示，平台代扣的交易卖家不需要再次缴税但需要在申报中体现。

这样做的好处是：国家差异收敛到「每个国家对每一类的处理」这张表里，而不是散落在几百行 if-else 中。新增国家时只需要补这张表。

系统内置了欧盟 27 国的跨境判断，已落地算税规则的有英国和德国、法国、意大利、西班牙、波兰、捷克、荷兰、奥地利 8 个欧盟国家。

## 进项抵扣：C79、C88 与 PVA

英国的进口环节是算税里最容易漏的部分，系统单独处理三类凭证：

- C79：英国海关签发的进口增值税证书，是进口 VAT 抵扣的依据。系统按申报周期收集 C79 金额计入进项抵扣
- C88：进口报关单。用于核对进口货值与税额，也作为抵扣凭证的一部分
- PVA（Postponed VAT Accounting）：进口增值税递延。卖家在进口时不实际缴税，而是在 VAT 申报中同时申报销项和进项。系统把 PVA 金额同时计入对应栏位，净效果为零但必须体现

这三类数据不在亚马逊报告里，需要卖家单独上传，所以在申报工作台里是独立的材料项，带缺失提醒。

## 输出：生成英国 VAT Return 各栏位

英国 VAT Return 有固定的申报栏位（Box 1 至 Box 9），分别对应销项税、欧盟取得税、进项税、净税额、销售与采购总额、欧盟内供应与取得额等。前面的 7 类归类加上 C79 / C88 / PVA 处理完成后，各栏位的数字可以直接推导出来，不需要会计再手工对表。

对欧盟 8 国，我们按各国申报表的结构输出对应的汇总数字。

## 多币种与汇率

亚马逊报告里的交易币种不一定等于申报币种。系统每日自动采集汇率，按交易日期折算。汇率来源和折算日期写入算税记录，审核时可以追溯。

## 流程：把算税放进申报工作台

算税不是孤立的工具，而是申报流程的一个节点。整个工作台的状态流转是：待上传报表 → 待确认税金 → 待提交申报 → 事务所申报中 → 待缴纳税金 → 申报完成。

- 卖家端：上传亚马逊报告和抵扣凭证，看到系统算出的税金，确认后提交
- 运营端：算税审核、申报审核、付款凭证与回执管理，角色权限与审计日志

把算税放进流程里，卖家看到的是「这期要交多少、为什么」，而不是一个需要自己解读的 Excel。

## 工程上的几点保障

税务数据出错的代价很高，我们在工程上做了几件事：

- 20 个端到端自动化测试覆盖主要算税路径
- 上线前做数据库结构比对，避免迁移遗漏字段
- 算税结果保留原始行级数据到汇总的映射，审核时可以从汇总数字一路追到具体交易

这套平台约 4 个月完成 300+ 次迭代，包含约 44 个业务页面、77 个 API 接口、19 个数据模型，技术栈是 React 19 + TypeScript + Koa + MySQL，OCR 与对象存储用阿里云。

## 给 VAT 服务商的建议

如果你在考虑把人工算税做成系统，建议从这几点开始：

1. 先把自己的算税规则写成「分类 × 国家」的表，这一步不需要写代码，但能暴露规则里的模糊地带
2. 抵扣凭证和平台报告分开建模，它们的来源和周期不同
3. 算税结果要可追溯到行，审核人员才敢签字
4. 先做英国和一两个欧盟国家，跑通流程再扩国家
