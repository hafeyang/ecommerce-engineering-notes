# Shopify 还是 Medusa？给品牌出海团队的独立站选型框架

> 原文发布在绯星科技博客：https://www.feixingtech.cn/blog/shopify-vs-medusa/

「我们要做独立站，用 Shopify 还是自己搭？」这是我们被问得最多的问题。常见的回答要么是「Shopify 省事」，要么是「开源自由」，都对，但都不足以做决定。

这篇文章给一个可以直接套用的判断框架。我们同时做 Shopify 开发和基于 MedusaJS 的 Headless 独立站，两边的坑都踩过，所以尽量不偏向任何一方。

## 先说清两条路线各是什么

**Shopify / Shopify Plus**：SaaS 电商平台。店铺、结账、支付、库存、订单都由平台托管，你通过主题（Liquid）定制前台，通过 App 和 API 扩展功能。Shopify Plus 在多店铺、结账定制和自动化上能力更强，面向体量更大的品牌。

**Headless / Composable 独立站（以 MedusaJS 为例）**：把前台购物体验和电商核心服务（商品、订单、支付、会员等）解耦。后端用开源电商框架为底座，配合定制 API、数据库和对象存储；前台独立开发，可以自由设计和迭代。代码、数据和部署环境都由你掌控，没有平台佣金，代价是需要自己（或服务商）负责部署和运维。

## 六个判断维度

### 1. 业务流程和平台的契合度

问自己：我的下单、履约、售后流程，Shopify 的标准流程能不能覆盖 80% 以上？

能覆盖的，走 Shopify。剩下 20% 的差异通常可以用主题定制和私有 App 补齐。我们为一家新能源储能品牌做的 Shopify 全站，产品线从可以直接零售的充电桩到需要询盘的集装箱储能系统，跨度很大。做法是零售产品直接下单，大型储能产品走资料下载和询盘，4 大产品线 11 个子类的信息架构都在 Shopify 内完成，没有必要自建。

如果你的核心流程本身就和标准电商不一样，比如定制化报价、多方协同履约、复杂的会员分级，平台会一直在限制你，这时候才考虑 Headless。

### 2. 对定制深度的真实需求

很多团队高估了自己的定制需求。Shopify 主题层能做的比想象中多。我们为一家智能健身器材品牌在 Shopify 主题内自研了一整套会员积分体系：会员中心、任务赚积分、积分流水、优惠券兑换、品牌 App 账户绑定，6 个子页面全部基于自定义 Section + Alpine.js 实现，不依赖第三方 Loyalty 应用，已在美区、欧区站点上线。

判断标准不是「想不想定制」，而是「定制的东西是否触碰结账流程和核心数据模型」。前台体验和周边功能，Shopify 够用；要改结账逻辑或者数据模型本身，Shopify Plus 能解决一部分，再往下就是 Headless 的领地。

### 3. 数据归属和长期成本

Shopify 的数据在平台上，可以通过 API 导出，但业务逻辑和平台绑定。平台佣金和 App 订阅费会随 GMV 增长。

Headless 独立站没有平台佣金，数据在自己的数据库里，但要承担服务器、运维和持续开发的成本。这不是一次性投入，而是长期的工程能力要求。

简单的算法：如果你没有或不打算有技术团队（内部或长期合作的服务商），不要选 Headless。

### 4. 多市场与本地化

两条路线都支持多语言、多币种、多市场。

Shopify Markets 可以配置不同国家的货币、域名和定价，我们在新能源品牌的项目里配置了美国（USD）和印度（INR）两个市场，印度使用独立域名并配置 hreflang，都是平台内的标准能力。

Headless 方案在本地化内容、税费规则、配送策略和区域化营销上更自由，适合市场间差异大、需要深度区域化运营的品牌。

### 5. 与内部系统的对接

品牌到了一定规模，店铺要和 ERP、CRM、库存系统打通：实时更新库存避免超卖、把客户数据同步到 CRM、订单回传给仓储。

Shopify 这条路线是通过 API 开发私有应用（Custom App），实现订单、库存、商品和客户数据与内部系统的双向同步，开发时对通信加密并按角色设置权限。周边系统（产品中心、订单中心、发货管理、数据报表、广告成本分析、供应链管理）可以独立于店铺之外搭建，通过 API 与 Shopify 交换数据。

Headless 这条路线里，这些对接是你自己的后端的一部分：支付可以集成 Stripe、PayPal 和本地支付通道，配合订单校验和异常拦截；物流可以对接物流商、仓储系统和运费规则，支持发货状态同步与物流追踪。自由度更高，但每一项都是要开发和维护的代码。

### 6. 上线时间和团队现状

Shopify 从零到上线可以很快，运维几乎为零。Headless 从设计、开发到部署的周期更长，上线后还需要有人负责访问控制、数据备份、日志监控和灰度发布。

团队刚起步、要先验证市场，选 Shopify。已经有稳定销量、知道自己要什么、准备长期投入，再考虑 Headless。

## 一张决策表

| 你的情况 | 倾向 |
|---|---|
| 标准电商流程，想快速上线 | Shopify |
| 需要前台体验定制、会员、营销模块 | Shopify + 主题 / App 定制 |
| 多店铺、结账定制、自动化需求 | Shopify Plus |
| 业务流程与标准电商差异大 | Headless |
| 对数据归属、平台佣金敏感，有技术团队 | Headless |
| 没有技术团队 | Shopify |

## 常见误区

- **「Shopify 慢，所以要自建」**：Shopify 店铺的性能问题大多来自主题代码、过多的第三方 App 脚本和未优化的图片，这些在主题层面都能治理，不需要换平台
- **「开源就是免费」**：框架免费，工程不免费
- **「先用 Shopify，以后再迁移」**：可以，但迁移成本随数据量和定制深度增长，最好在第一次选型时就想清楚两三年内的方向

## 我们的建议

先了解业务阶段和团队情况，再定方案，不要先定技术再找理由。如果你拿不准，把自己的下单流程、现有系统和未来两年的目标写下来，对着上面六个维度逐条过一遍，答案通常会自己浮现。

还有一点经常被忽略：上线不是终点。无论哪条路线，店铺上线后都会有问题排查、功能迭代和性能优化的持续需求。选型时就要想清楚这部分由谁负责，是内部团队、长期合作的服务商，还是指望平台客服。这个答案本身往往就决定了该选哪条路。
