# 用 DeepSeek 和元宝的搜索 API 做 GEO 监测：一次 22 个查询的实测

> 首发于掘金：https://juejin.cn/post/7701559825633230884

10 月 17 日，DeepSeek 开放了自研搜索引擎的 Search / Fetch API；10 月 20 日，腾讯通过腾讯云开放了元宝搜索。对做 GEO（生成式引擎优化）的人来说，这件事的意义是：AI 回答背后的那一层检索，第一次可以直接调用、直接测量了。

我们测了一轮，AI 回答里约 77% 的引用来自搜索结果的前 10 名。所以一篇内容没有被 AI 引用，原因大致只有三种：

- **没检索到**：没被收录，或者内容和问题对不上
- **检索到了，但排名靠后**：权威度或相关度分数不够
- **进了前 10，但没被引用**：内容本身不如其他结果好用

以前这三种情况混在一起，只能凭感觉猜。现在用搜索 API，可以逐条查清楚。下面是我们用 22 个业务查询，测自己网站和站外文章的完整过程和数据。

## 两个 API 怎么调

**DeepSeek Search API**

- 地址：`POST https://api.deepseek.com/v1/tools/search`，和对话 API 用同一个 Key
- 参数：`query`（必填）、`count`（1–50，默认 10）、`ori_question`（用户原始问题，帮助理解查询）、`need_content`（是否返回正文）
- 支持搜索语法：`site:`、`-site:`、`lang:`、`after:`、`before:`、双引号精确匹配
- 价格：每千次 $0.75（约 5 元），只对返回结果的成功请求计费，限流每个接口 5 QPS

返回结果里有两个字段对 GEO 特别有用：

- `rerank_score`：0–3 的排序分，综合了相关度、权威度和新鲜度，1.5 以上算高质量
- `authority`：0–4 的权威度分级，3 及以上算高权威，-1 表示未知

另外还有一个 Fetch API（`/v1/tools/fetch`），给它一个 URL，它会返回页面的 Markdown 正文。可以直接用来检查自己的页面在 AI 眼里长什么样，比如关键内容是不是依赖 JS 渲染、抓回来是不是空的。

**元宝搜索 API（腾讯云）**

- 地址：`POST https://api.wsa.cloud.tencent.com/SearchPro`，`Authorization: Bearer <API KEY>`
- 参数：`Query`（必填）、`Cnt`（返回条数，实测最多 50）、`Site`（限定站点）等
- 价格：标准版后付费每千次 20 元
- 返回的 `Pages` 是一个字符串数组，每个元素要再 `JSON.parse` 一次，里面有 `url`、`title`、`passage`、`score`（0–1）、`date`、`site`
- 没有类似 DeepSeek `authority` 的权威度字段

两个小坑：

- 元宝开通后创建的 API KEY 一直返回 `UnauthorizedOperation`。最后发现是我们自己的问题：把 Key 追加进 `.env` 时，原文件最后一行没有换行符，Key 被拼到了上一行后面。如果你遇到同样的报错，先检查 Key 本身有没有被截断或拼接。
- 两边的分数不能直接比较：DeepSeek 的 `rerank_score` 范围是 0–3，元宝的 `score` 范围是 0–1，而且计算方式不同。只用来比较同一家搜索内部的排名。

## 监测脚本

思路很简单：准备一组查询，每条查询取前 50 个结果，看我们自己的链接有没有出现、排第几，再记下第 10 名的分数作为「门槛」。

查询按业务来写，22 条，包括品牌词、服务商词（如「深圳 Shopify 开发公司推荐」）、问题词（如「外贸网站打开很慢怎么优化」）和英文词。「我们的链接」不只是官网域名，也包括我们在公众号、知乎、掘金上发的每篇文章的 URL。

核心逻辑大约 30 行：

```js
const results = await search(query); // 统一成 { url, score, authority }
const hits = results
  .map((r, i) => ({ rank: i + 1, ...r }))
  .filter((r) => ours.some((m) => r.url.includes(m)));
const best = hits[0];
const status = !best ? "missing" : best.rank <= 10 ? "top10" : "low";
const top10 = results.slice(0, 10);
const bar = {
  score10: top10.at(-1)?.score,                       // 进前 10 的门槛
  authorityMedian: median(top10.map((r) => r.authority)),
};
```

每次运行把结果存成 JSON，按日期命名，之后每周跑一次就能看到趋势。22 条查询每次大约 44 次调用（两家各一次），按上面的价格算，一个月花不到 3 元。

## 实测结果

**DeepSeek：7 条进前 10，5 条排名靠后，10 条没检索到**

| 查询 | 我们的最好排名 | 我们的分数 | 第 10 名分数 |
|---|---|---|---|
| 亚马逊 VAT 报告 C79 PVA 处理 | 第 1 | 1.30 | 1.01 |
| 独立站选型 Shopify 还是 Headless | 第 3 | 1.59 | 1.36 |
| Shopify 还是 Medusa 怎么选 | 第 4 | 1.70 | 1.58 |
| B2B 外贸官网 TTFB 优化 | 第 6 | 1.60 | 1.45 |
| MedusaJS 独立站 开发 | 第 11 | 1.47 | 1.47 |
| 外贸网站打开很慢怎么优化 | 第 17 | 1.58 | 1.80 |
| 网站 Lighthouse 分数低 怎么提升 | 第 23 | 1.48 | 1.74 |
| 亚马逊 VAT 计算报告 怎么算税 | 第 35 | 1.10 | 1.54 |

几个发现：

1. **所有命中都来自掘金。** 文章发出 2 天就被收录，并且在长尾问题上能排进前 10。同样的文章，知乎和公众号的版本用标题精确搜也搜不到。
2. **官网一页都没有被收录。** `site:` 查询返回空。但用 Fetch API 去抓，正文能完整取回，robots.txt 也放行了 AI 爬虫，所以不是技术原因，是还没被发现。
3. **排名靠后的查询，差的主要是权威度。** 我们所有命中的 `authority` 都是 2，而前 10 名的权威度中位数大多是 3。分数接近时，权威度更高的结果排在前面。
4. **「找服务商」类查询基本被目录站占了。** 前 10 名里出现次数最多的是 upwork.com（10 次）、shopify.com（9 次）、designrush.com（6 次）。这类查询光靠写文章很难进前 10。

**元宝：22 条全部没检索到**

我们的官网、掘金、知乎、公众号内容都不在元宝的结果里，用标题精确搜也找不到。元宝的前 10 名和 DeepSeek 差别很大：同一家建站公司的城市分站页面在 22 个查询的前 10 名里占了 15 个位置。两家的索引和排序逻辑明显不同，只看一家得出的结论不能直接套用到另一家。

## 按诊断结果做了什么

- **没检索到（官网）**：DeepSeek 没有站长提交入口，只能靠已被收录的页面里的外链让爬虫发现。我们把文章合集放到了 GitHub（在 DeepSeek 里 `authority` 为 3），并在搜狗站长平台验证了网站、提交了收录，因为元宝的底层技术来自搜狗。
- **排名靠后（权威度不够）**：补权威度高的站外主页，比如 GitHub、Clutch 这类服务商目录。
- **找服务商的查询**：在目录站建立公司主页，让目录站自己的页面排名带着我们出现。

这些动作的效果要过一两周才能在数据里看到，我们会继续每周跑脚本跟踪。

## 写在最后

搜索 API 解决的是「能不能被检索到、排第几」这一层。它不能告诉你 AI 最终引用了谁，要回答这个问题，还需要用对话接口带同样的问题跑一遍，对比引用的链接和检索结果。但只做检索这一层，就已经能把「AI 不引用我」这个模糊的问题，拆成可以逐条处理的具体原因。
